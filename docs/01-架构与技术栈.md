# 架构与技术栈

## 1. 进程

浏览器只和两个进程说话：页面开发服务器，以及网关。业务服务之间除了对话服务调用地图服务，没有别的内部 RPC。

```text
浏览器  5173  Vite（开发时把 /api 代理到 8080）
           │
           ▼
        网关 8080  map-gateway     不连数据库
           │
           ├── /api/ingest/**     入库 8081  map-ingest   写 PostGIS
           ├── /api/geo/**        地图 8082  map-geo      只读 PostGIS
           ├── /api/tiles/**      地图 8082
           └── /api/ai/**         对话 8083  map-ai       读写模型表，HTTP 调用 8082
                                      │
                                      ▼
                              PostgreSQL 16 + PostGIS
                              库 ai_open_map  localhost:5432
```

| 模块 | 端口 | 数据库 | 职责 |
| --- | --- | --- | --- |
| map-gateway | 8080 | 无 | 路由、CORS、120 秒响应超时 |
| map-ingest | 8081 | 读写 | 下载 PBF、解析、发布要素、定时任务 |
| map-geo | 8082 | 只读 | 矢量切片、图层统计、搜索、视野分析 |
| map-ai | 8083 | 读写 `ai_model_config` | 模型配置、规则对话、可选大模型 |
| frontend | 5173 | 无 | 地图、图层、任务、对话 |

公共返回体是 `ApiResult`：`code = 0` 成功，失败时 `code = 1` 且 `message` 给页面。切片接口例外，成功时正文是 protobuf，不是 JSON。

## 2. 一次对话怎么走到地图上

以“分析当前视野内的道路里程”为例。

1. 页面把当前视野 `bbox` 和这句话 `POST` 到 `/api/ai/chat`。
2. 规则引擎看到“分析”和“道路”，生成 `followUp`：`analyze` + `highway`。它不自己算长度。
3. `ChatService` 用 `RestClient` 请求地图服务的 `/api/geo/analyze`，带上视野四至。
4. 地图服务在 PostGIS 里做相交计数和 `ST_Length(geography)`。
5. 对话服务把句子和表格放进 `ChatResponse`。页面渲染表格。这个指令没有 `fly_to`，地图不移动。

“定位到合肥”则在规则内部就结束：动作是 `fly_to`，中心 `[117.227, 31.821]`，缩放 11。城市坐标写在 `RuleDialogueEngine` 的常量表里，不查库。查库的是“合肥市”这个地名要素，那是搜索接口的事。

启用模型之后，规则仍然优先。只有规则没有识别时，才把系统提示和用户话发给模型，并要求 JSON。模型密钥在列表接口里打码；更新时如果密钥留空，保留原值。密钥可以为空，这样本机 Ollama 一类不需要密钥的服务也能用。地址按 OpenAI 兼容处理，会补上 `/chat/completions`。

## 3. 技术栈和版本

| 层 | 选择 | 版本 |
| --- | --- | --- |
| 语言 / 运行时 | Java | 17 |
| 应用框架 | Spring Boot | 3.2.12 |
| 微服务 BOM | Spring Cloud | 2023.0.3 |
| 阿里组件 BOM | Spring Cloud Alibaba | 2023.0.3.4 |
| 网关 | Spring Cloud Gateway | 随 Spring Cloud |
| 注册发现 | Nacos Discovery | 代码在，默认关闭 |
| 连接池 | Alibaba Druid | 1.2.23（`druid-spring-boot-3-starter`） |
| ORM | MyBatis | `mybatis-spring-boot-starter` 3.0.4 |
| 数据库 | PostgreSQL + PostGIS + pg_trgm | 16.2 / 3.4.1 |
| OSM | Osmosis `OsmosisReader` | 0.48.3 |
| 前端 | React、TypeScript、Vite、Ant Design | 18.3 / 5.7 / 6.2 / 5.24 |
| 地图 | MapLibre GL | 5.6 |

MyBatis 启动器默认会带 HikariCP。各业务模块排除了它，数据源只由 Druid 创建。三个连库服务都 `spring.config.import: classpath:datasource-druid.yml`，再在自己的配置里覆盖池名称和 `max-active`：入库 8，地图 16，对话 4。

Druid 内置监控打开着：

- 地址：`http://127.0.0.1:{端口}/druid/`
- 账号：`admin` / `admin`，可用环境变量 `DRUID_USER`、`DRUID_PASSWORD` 覆盖
- SQL 监控、URI 监控、慢 SQL（超过 2 秒）都开着
- `merge-sql` 关闭，原因见[构建过程](00-构建过程.md)

## 4. 为什么是这套，而不是看起来更满的微服务

**注册中心默认关闭。** 四个进程都在本机，固定端口比先装 Nacos 更容易把数据跑通。需要注册发现时，四个服务同时加上 `--spring.profiles.active=cloud`，并先启动 Nacos（`NACOS_ADDR`，默认 `127.0.0.1:8848`）。网关路由从 `http://127.0.0.1:808x` 换成 `lb://服务名`。

**一个地图服务同时管切片和查询。** 它们共享白名单、图层顺序和同一张表。拆成两个部署单元不会减少 PostGIS 的工作。

**规则引擎放在模型前面。** “显示道路”这种指令不需要网络，结果也可测试。`RuleDialogueEngineTest` 锁的就是这些句子。模型负责规则覆盖不到的说法，并且仍然只能通过 `followUps` 触发已经写好的查询。

**MapLibre 而不是带 token 的 Mapbox 样式。** 矢量瓦片格式仍然是 Mapbox Vector Tile。底图是 Carto 的栅格，业务数据全部来自本机 PostGIS。断网时底图会空，本地道路图层还在。

**关系不入库。** PBF 里的 relation 成员多、几何要再组装，0.1 的道路和建筑主要来自 way。这是范围选择，不是解析器漏读。

## 5. 配置入口

| 文件 | 作用 |
| --- | --- |
| `pom.xml` | 版本和对五个模块的聚合 |
| `backend/map-common/src/main/resources/datasource-druid.yml` | 数据源、Druid 监控、MyBatis |
| `backend/*/src/main/resources/application.yml` | 端口、路由、OSM 区域、地图服务地址 |
| `backend/*/src/main/resources/application-cloud.yml` | 打开 Nacos |
| `sql/schema.sql` | 建表，入库服务启动时也会执行 |
| `frontend/vite.config.ts` | 5173，以及 `/api` → 8080 |

环境变量：

| 变量 | 默认 | 作用 |
| --- | --- | --- |
| `DB_URL` | `jdbc:postgresql://localhost:5432/ai_open_map` | JDBC |
| `DB_USER` / `DB_PASSWORD` | `postgres` / `post` | 数据库账号 |
| `OSM_DATA_DIR` | 相对路径 `../../data/osm` | PBF 存放目录，启动脚本会设成绝对路径 |
| `DRUID_USER` / `DRUID_PASSWORD` | `admin` / `admin` | 监控台 |
| `NACOS_ADDR` | `127.0.0.1:8848` | 仅 cloud 配置 |
