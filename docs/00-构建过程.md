# 构建过程

这篇文档按真实落地顺序写，方便对照代码学习。数字、报错和取舍都来自这次本地构建，不是事后想象的理想流程。

## 1. 最后做成了什么

一个仓库里有四件能一起工作的东西：

1. **入库服务**下载安徽省 OSM PBF，解析后写入 PostGIS。
2. **地图服务**按图层生成 Mapbox Vector Tile，并提供统计、搜索、视野分析。
3. **对话服务**先用中文规则理解指令，需要时再调用已启用的 OpenAI 兼容模型，然后让地图飞到、显隐图层、打点、出表。
4. **React 页面**把图层、任务进度、地图和对话框放在一起。浏览器只访问网关。

## 2. 构建顺序

没有先把五个模块的空壳全部生成再填逻辑，而是按数据能否流动来推进。后一步依赖前一步的真实数据。

### 2.1 父工程、库表和公共模块

根目录 `pom.xml` 是聚合工程，父级为 Spring Boot 3.2.12。模块是：

- `backend/map-common`：统一返回体、图层名单、异常处理和 Druid/MyBatis 公共配置
- `backend/map-ingest`：下载、解析、入库
- `backend/map-geo`：切片和空间查询
- `backend/map-ai`：模型配置和对话
- `backend/map-gateway`：对外唯一入口

数据库脚本在 `sql/schema.sql`。`scripts/init-db.ps1` 在库不存在时创建 `ai_open_map`，再用 UTF-8 执行脚本。入库服务启动时也会执行同一份脚本（`spring.sql.init.mode=always`），语句都写成 `IF NOT EXISTS`，所以重复启动是安全的。

这一阶段提交过一次：`初始化入库服务，用 Druid 和 MyBatis 接入 PostGIS。` 当时父 POM 还只包含 common 和 ingest。后面的模块是在同一份 POM 上继续加的，因此不能把“只含 geo、不含 ai”的中间状态单独检出编译。阅读历史时，以当前树为准。

### 2.2 入库服务

默认区域写在 `map-ingest` 的 `application.yml`：

- 名称：安徽省
- 地址：`https://download.geofabrik.de/asia/china/anhui-latest.osm.pbf`
- 校验：同目录的 `.md5`
- 请求头：`User-Agent: AIOpenMap/0.1 (local WebGIS)`
- 定时：每天 03:00（`0 0 3 * * ?`），页面也可以 `POST /api/ingest/jobs` 手动触发

解析用 Osmosis 0.48.3 的 `OsmosisReader`，一次扫描文件。先记住节点的经纬度（放大 1e7 后放进 `Long2LongOpenHashMap`），再在遇到 way 时组装几何。分类规则在 `OsmTagClassifier`：建筑、道路、铁路、水系、用地、边界、地名、兴趣点各归一个 `layer`，细类放进 `sub_type`。规划中、废弃、信号灯这类不是线状道路的 `highway` 值会被丢掉。

写入分两段，避免地图读到半成品：

1. `COPY` 进无日志表 `osm_feature_stage`。MyBatis 做不了 PostgreSQL 的 `COPY FROM STDIN`，所以这里直接从 Druid 连接上拆出 `BaseConnection`，用驱动的 `CopyManager`。
2. 一个事务里发布：去掉正式表索引、清空、`ST_GeomFromText` 写入、重建 GIST / btree / GIN、`ANALYZE`。

同一时刻只允许一个 `RUNNING` 任务，靠部分唯一索引保证。服务启动时会把上次异常留下的 `RUNNING` 标成失败。

### 2.3 地图服务

`osm_feature.layer` 就是矢量切片的 source-layer 名。一个图层一次请求，前端每种要素各挂一个 MapLibre source。这样“只显示道路”不用在一个混合瓦片里再过滤类型。

SQL 在 `TileMapper.xml`：

- `ST_TileEnvelope(z, x, y)` 得到 Web Mercator 瓦片范围
- 用 `&&` 和 4326 范围先做空间过滤，GIST 索引才能用上
- 低缩放级别 `ST_SimplifyPreserveTopology`，避免全省道路在 z=6 时过密
- `ST_AsMVTGeom` 把几何裁进 4096 的瓦片坐标
- `ST_AsMVT` 打成 protobuf

道路、建筑、地名还有按缩放级别丢细节的条件。例如 z < 11 时道路只留高速、国道、省道、县道这一档，z < 13 不输出建筑和兴趣点。

查询接口和切片放在同一个服务里，因为它们读同一张表：图层计数、子类统计、名称搜索、视野内数量/长度/面积。

### 2.4 对话服务和网关

对话不把模型当成唯一入口。`RuleDialogueEngine` 能直接识别“显示道路”“定位到合肥”“统计道路数量”“查找大学”“分析当前视野内的道路里程”。识别成功就不再请求模型。没有命中、并且数据库里有一个启用的模型时，才把最近对话交给 OpenAI 兼容的 `/chat/completions`，要求它返回 JSON：`reply`、`actions`、`followUps`。

需要查库的动作不让模型直接写 SQL。模型或规则只产生 `followUps`（统计、搜索、分析），`ChatService` 再用 HTTP 调用地图服务，把数字和标记填回回复。

网关不连数据库。默认把 `/api/ingest/**`、`/api/geo/**`、`/api/tiles/**`、`/api/ai/**` 转到本机 8081、8082、8083。Nacos 依赖已经放进工程，但默认关闭。`application-cloud.yml` 才改成 `lb://map-ingest` 这类服务名。Sentinel、Seata、RocketMQ 没有放进运行路径，0.1 用不上它们。

网关是 WebFlux，不能去扫描 `map-common` 里基于 Servlet 的 `ApiExceptionHandler`，所以 `GatewayApplication` 只扫自己的包。

### 2.5 前端

Vite 6 + React 18 + TypeScript + Ant Design 5 + MapLibre GL 5。没有用 Mapbox GL 的官方托管样式，因为那需要 token。MapLibre 读的是同一套 Mapbox Style 规范，底图用 Carto 的浅色栅格，中文注记用本机微软雅黑（`localIdeographFontFamily`），避免再拉一份字形服务。

页面布局：

- 顶栏：标题、当前任务或“安徽省”、模型配置
- 左侧：图层开关（带库内数量）和入库任务
- 中间：地图，默认中心 `[117.28, 31.86]`，缩放 6.4，大约能看到全省
- 右侧：对话

默认打开道路、水系线、水体、地名、行政区划。建筑和兴趣点要放到 z=13 附近才有瓦片，这是服务端和样式两边一致的选择。

开发时 Vite 把 `/api` 代理到 `8080`。生产构建命令是 `tsc --noEmit && vite build`。

## 3. 构建过程中真正遇到的问题

这些错误比“功能清单”更值得看，因为它们决定了现在代码为什么长这样。

### 3.1 不能在父 POM 上执行 spring-boot:run

`mvn spring-boot:run -pl map-ingest` 会作用到聚合 POM，报 `Unable to find a suitable main class`。可运行的入口在各模块打出来的 jar 里。启动方式是：

```text
java -jar backend/map-ingest/target/map-ingest-0.1.0.jar
```

工作目录使用仓库根目录，并用 `OSM_DATA_DIR` 指向 `data/osm` 的绝对路径。配置里的默认相对路径 `../../data/osm` 只在“当前目录是 `backend/map-ingest`”时才对。

### 3.2 Druid 合并 SQL 吃不消 PostGIS 的建表语句

第一次启动入库服务时，Druid 的 StatFilter 对 `CREATE EXTENSION`、部分唯一索引、GIN、`UNLOGGED TABLE` 报 `merge sql error`。语句本身执行成功了，报错来自监控把 SQL 归一化。公共配置 `datasource-druid.yml` 里把 `filter.stat.merge-sql` 设成 `false`。慢 SQL 仍然记录，只是不再尝试合并。

监控过滤器只用 `stat`，没有开 `wall`。Wall 是 MySQL 方言的防火墙，套到 PostGIS 上会误伤。

### 3.3 重新打包时 jar 被正在运行的进程锁住

`spring-boot:repackage` 要把旧 jar 改名为 `*.jar.original`。Windows 上，正在 `java -jar` 的进程占着文件，Maven 报 `Unable to rename`。正确顺序是先停掉该端口上的进程，再 `package`，再启动。`scripts/stop-all.ps1` 只结束命令行里带本项目 jar 名的 `java.exe`，不会动 IDE 自己的语言服务进程。

### 3.4 矢量切片返回 argument type mismatch

`GET /api/tiles/highway/6/52/25.pbf` 最初是 HTTP 400，正文只有 `{"code":1,"message":"argument type mismatch"}`。PostgreSQL 的错误在这台机器上是中文，所以这不是 SQL 语法错误，而是 Java 反射抛出的 `IllegalArgumentException`。

MyBatis 内置别名里，`byte[]` 指向的是装箱类型 `Byte[]`，不是 `byte[]`。PostGIS 的 `ST_AsMVT` 返回 `bytea`，JDBC 给出原始字节数组，两边对不上。把 `resultType` 改成 `_byte[]`（MyBatis 里原始字节数组的别名）之后，这个请求仍然是同样的 400。

最后采用的办法写在 `TileMapper.xml`：SQL 里 `encode(..., 'base64')`，映射成普通字符串；`TileService` 再用 `Base64.getMimeDecoder()` 解码。PostgreSQL 的 base64 每 76 个字符会换行，必须用 MIME 解码器。修好后，同一块瓦片返回 200，`Content-Type` 为 `application/vnd.mapbox-vector-tile`，大小 1,192,058 字节。protobuf 开头能看到图层名 `highway`。

同级别的水体瓦片约 68 KB，地名瓦片约 31 KB。某个缩放级别下一块瓦片是 0 字节且状态 200，表示这块范围里没有该图层的要素，不是错误。

### 3.5 搜索参数是 NULL 时 PostgreSQL 无法推断类型

`GET /api/geo/search?keyword=合肥` 报：`无法确定参数 $3 的数据类型`。SQL 里写了 `#{layer} IS NULL OR layer = #{layer}`。Java 传入 `null` 时，JDBC 给不出类型，PostgreSQL 不能判断这个参数是什么。

改法是别把“可空条件”写成一个参数。`GeoQueryMapper.xml` 用 MyBatis 的 `<if test="layer != null and layer != ''">`，没有图层时整段条件不出现。`LIKE` 的转义符改成 `!`，在 Java 里把 `!`、`%`、`_` 替换掉。反斜杠在 XML 和 JDBC 里都容易多转义一次。

修好后，搜索“合肥”能回到地名“合肥市”（约 117.281, 31.867）。

### 3.6 前端 Source 上没有 setData

`map.getSource('markers')` 的类型是 `Source` 联合类型，`setData` 只在 `GeoJSONSource` 上。`source.type === 'geojson'` 也不能让 TypeScript 收窄。`MapView` 改成 `source instanceof GeoJSONSource` 之后，`npx tsc --noEmit` 和 `npm run build` 都通过。构建产物约 2.1 MB（gzip 约 619 KB），主要体积来自 MapLibre 和 Ant Design，Vite 提示单包超过 500 KB。0.1 没有再拆包。

### 3.7 其他环境问题

- `map-common` 最初的异常处理用了 SLF4J 和 `DataAccessException`，但模块没声明这两个依赖，编译失败。后来补上可选依赖。
- PowerShell 会把 bash 风格的 heredoc 当成重定向，Git 提交信息改由 Git Bash 执行。
- Windows 控制台经常把 UTF-8 的中文打成乱码。判断接口是否正确时看落盘的 UTF-8 文件，不看控制台。
- 第二次启动地图服务时，旧进程还占着 8082，新进程日志里是 `Port 8082 was already in use`。看端口占用进程，不要只看“我刚才启动的那个 PID”。

## 4. 联调时实际打过的请求

服务都通过网关 `127.0.0.1:8080` 访问，地图服务本身在 8082。

| 请求 | 结果 |
| --- | --- |
| `GET /api/geo/layers` | 九个图层及上表数量 |
| `GET /api/tiles/highway/6/52/25.pbf` | 200，1,192,058 字节 |
| `GET /api/tiles/water/6/52/25.pbf` | 200，69,742 字节 |
| `GET /api/tiles/place/6/52/25.pbf` | 200，31,869 字节 |
| `GET /api/geo/search?keyword=合肥` | 命中“合肥市” |
| `GET /api/geo/analyze?layer=highway&minLon=117&minLat=31.6&maxLon=117.5&maxLat=32` | 29,025 条道路，长度约 13,600 公里 |
| 对话“定位到合肥” | 规则引擎，`fly_to` 到 `[117.227, 31.821]`，缩放 11 |
| 对话“统计道路数量” | 道路合计 217,088，并给出子类表（未分类、居住区道路、高速公路等） |
| 对话“查找大学” | 规则引擎按名称包含“大学”找 8 条，打点并飞到第一条 |
| 对话“分析当前视野内的道路里程” | 视野 `[117.1, 31.7, 117.4, 32.0]` 内 22,302 条，约 9,535.8 公里 |

“查找大学”匹配的是名称或子类里包含这几个字的要素，所以结果里会有“大学生活动中心”，不一定是 `amenity=university`。这是当前规则的行为：去掉“查找”之后，把剩下的词交给 `ILIKE`。

视野分析用 `geom && 矩形`，统计的是与矩形相交的整条要素，不是把路按视野边界切短。回复里写了这句话。长度用 `ST_Length(geom::geography)`，单位是米。

`mvn` 测试覆盖了入库侧的分类样例和对话规则。前端 `npm run build` 成功。没有在真实浏览器里点击地图、拖拽和打开弹窗；当前环境没有浏览器自动化工具。接口、瓦片字节和生产构建是已核对的部分。

## 5. 读代码时建议的路径

1. `sql/schema.sql`：先看数据长什么样。
2. `OsmTagClassifier` → `OsmImporter` → `FeatureRepository`：一条 way 怎么变成一行。
3. `TileMapper.xml` → `TileService` → `GeoController`：一行怎么变成瓦片。
4. `RuleDialogueEngine` → `ChatService`：一句话怎么变成地图动作。
5. `frontend/src/App.tsx` 和 `MapView.tsx`：动作怎么画出来。
6. `datasource-druid.yml`：三个连库的服务为什么配置长得一样。

对应的设计说明在同目录另外三篇文档里。
