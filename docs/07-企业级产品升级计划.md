> 基线：`main` 分支 0.1（2026-11）。
> 产品名沿用大赛定位：**智图灵 GeoMind**（下文简称 GeoMind）。
> 本版决策（2026-11-15 确认）：
>
> | 决策项 | 结论 |
> | --- | --- |
> | 目标客户 | 暂不锁定具体行业，先做通用功能场景；公测后按使用数据再决定行业方向 |
> | 交付形态 | SaaS 云服务为主；私有化部署放到后期 |

## 1. 现状评估

### 1.1 已有能力

| 领域 | 已实现 | 关键代码 |
| --- | --- | --- |

| 地图服务 | MVT 矢量切片（z0–16）、多省同图、进程内短时缓存、全国低缩放预生成（文件 + manifest）、图层统计 / 名称搜索 / 视野分析 | `map-geo` |

### 1.2 与 SaaS 产品的差距

| 维度 | 现状 | 分数（1–5） | 主要差距 |
| --- | --- | --- | --- |
| 账号与租户 | 无登录，所有人共用一份状态 | 1 | 缺注册登录、组织 / 团队、角色、数据隔离 |
| 工作空间 | 地图状态只存在浏览器 `localStorage` | 1 | 缺项目保存、分享、协作、版本 |
| 安全 | 默认口令 `postgres/post`、Druid `admin/admin`；CORS `*`；模型密钥明文入库 | 1 | 公网 SaaS 必须先解决 |
| 资源与成本控制 | 任何人可触发入库、无限调用模型 | 1 | 缺配额、限流、计量、套餐 |
| 部署运维 | PowerShell 脚本启动本机进程 | 1 | 缺容器、云上部署、CI/CD、监控告警 |
| 可靠性与扩展 | 入库任务在进程内线程池，重启即丢；切片缓存在进程内 | 2 | 需要无状态多实例、分布式缓存、CDN |
| 数据能力 | 只有 OSM 省级全量、9 个固定图层 | 2 | 缺用户数据上传、数据版本、质量校验 |
| 空间分析 | 矩形视野计数 / 长度 / 面积 | 2 | 缺任意范围、缓冲区、聚合、对比、路径 |
| AI 能力 | 单轮意图识别，模型只能输出受限 JSON | 2 | 缺工具调用、多步规划、会话记忆、可解释、评测 |
| 开放能力 | 无 | 1 | 缺 API Key、标准服务、嵌入 SDK |
| 工程质量 | 后端少量单测；前端无测试；无 CI | 2 | 缺测试体系与门禁 |
| 合规 | 有 OSM 署名 | 1 | 互联网地图服务资质、审图、ICP 备案、等保、个人信息、生成式 AI 备案未考虑 |

### 1.3 代码层面的技术债

1. **硬编码默认值**：`ChatService` 默认省份 `anhui`、默认视野是安徽四至；`RuleDialogueEngine` 城市坐标写死在常量表；前端初始中心也是安徽。
2. **cloud 模式不完整**：`map-ai` 调地图服务的 `app.geo.base-url` 是固定地址，多实例下不可用。
3. **任务模型不完整**：`ingest_job.status` 只有 `RUNNING / SUCCESS / FAILED`，没有排队、取消、重试；进程崩溃后 `RUNNING` 记录会残留并挡住该省后续任务。
4. **前端轮询**：任务日志和预生成状态 2 秒轮询，多人在线时数据库压力线性增长。
5. **底图外部依赖**：底图是 Carto 栅格，没有审图号，不适合国内公网服务。
6. **状态全在浏览器**：地图风格、省份选择存在 `localStorage`，换设备就丢，也无法分享。
7. **前端结构**：所有状态集中在 `App.tsx`（约 530 行），没有路由和状态管理层。
8. **仓库卫生**：根目录有未跟踪的 `ai-open-map.rar`；`logs/` 下有调试用 JSON 和二进制文件。

## 2. 产品定位

### 2.1 一句话

**GeoMind：用自然语言看懂一片区域的在线地图智能平台。** 用户不需要安装 GIS 软件、不需要会写空间 SQL，就能在全国开放地图数据和自己的数据上完成查询、分析、制图和报告，并把结果分享给团队。

### 2.2 设计原则

- **场景通用，行业中立**。功能按“看、查、算、比、出”五类通用动作设计，不写死任何行业术语和流程。
- **行业能力靠“场景模板”扩展**。行业差异放在模板（图层组合、分析步骤、提示词、报告格式）里，平台本身不改代码；公测后按使用数据挑方向深做。
- **AI 可解释**。每一次 AI 操作都能看到调用了哪些工具、用了哪些参数、等价的查询是什么，结果可复核。
- **数据由平台维护**。全国 OSM 数据平台统一入库、定期更新，用户开箱即用。

### 2.3 用户角色

| 角色 | 说明 |
| --- | --- |
| 平台运营 | 我方：入库与更新全国数据、管理组织与套餐、模型配置、内容审核 |
| 组织管理员 | 客户方管理者：管理成员、团队、角色、用量、账单 |
| 编辑者 | 创建和编辑项目、上传数据、运行分析、生成报告 |
| 查看者 | 只读查看被分享的项目和报告 |
| 外部访客 | 通过分享链接查看（可设密码与有效期） |
| 开发者 | 通过 API Key 调用地图与分析能力，或把地图嵌入自己的系统 |

### 2.4 套餐

| 套餐 | 内容 | 收费方式 |
| --- | --- | --- |
| 免费版 | 1 人；3 个项目；每日 AI 调用 30 次；不可上传数据；分享带水印 | 免费 |
| 专业版 | 1 人；不限项目；数据上传 1 GB；AI 月度额度；报告导出 | 按月 / 年订阅 |
| 团队版 | 多人协作、团队空间、角色权限、共享数据、用量看板 | 按席位订阅 |
| 企业版 | 团队版全部 + 单点登录、审计日志、API 与嵌入、更高额度、专属支持 | 年度合同 |
| 私有化版（后期） | 企业版全部 + 客户机房部署 + 国产化适配 | 项目制 |

## 3. 目标架构（SaaS）

```text
                Web 应用（React SPA：工作台 / 数据中心 / 组织管理 / 运营后台）
                                     │ HTTPS（CDN 加速静态资源与瓦片）
                     ┌───────────────▼────────────────┐
                     │ map-gateway  认证 · 租户识别 · 限流 · 配额 · 审计 │
                     └──┬────────┬─────────┬─────────┬────────┬────┘
                        │        │         │         │        │
              ┌─────────▼┐ ┌─────▼──────┐ ┌▼───────┐ ┌▼───────┐ ┌▼──────────┐
              │map-auth  │ │map-workspace│ │map-geo │ │map-ai  │ │map-ingest │
              │账号/组织 │ │项目/分享    │ │切片    │ │Agent   │ │平台数据   │
              │角色/SSO  │ │场景模板     │ │查询分析│ │工具/会话│ │用户上传   │
              │套餐/额度 │ │报告/评论    │ │标准服务│ │报告叙事│ │质检/版本  │
              └────┬─────┘ └─────┬──────┘ └───┬────┘ └───┬────┘ └────┬──────┘
                   │             │            │          │           │
     ┌─────────────┴─────────────┴────────────┴──────────┴───────────┴───────┐
     │ PostgreSQL + PostGIS：平台共享数据（OSM，只读）+ 租户数据（行级安全隔离） │
     │ 只读从库（切片、分析、SQL 工作台）  Redis  对象存储  消息队列  Nacos       │
     └─────────────────────────────────────────────────────────────────────────┘
       可观测：Prometheus + Grafana · OpenTelemetry · 集中日志 · 告警
       部署：容器镜像 + 云厂商托管 Kubernetes · 多可用区
```

关键设计：

- **数据分两层**。平台共享的 OSM 数据所有租户只读；租户上传的数据、项目、报告带 `tenant_id`，用 PostgreSQL 行级安全（RLS）隔离，防止代码漏写条件导致越权。
- **新增 `map-auth` 与 `map-workspace`**。前者管身份、组织、套餐；后者管项目、分享、场景模板、报告。现有入库 / 地图 / 对话三个服务的边界保持不变。
- **重查询走从库**。切片、分析、SQL 工作台全部打到只读从库，和写库隔离。
- **共享瓦片走 CDN**。平台数据的瓦片对所有租户一样，按数据版本号长缓存。
- **AI 只经工具访问数据**。模型不直接拼 SQL；SQL 工作台是单独的受限通道（见 4.4）。

## 4. 分领域功能规划

优先级：**P0** 公测必备，**P1** 正式商用必备，**P2** 增强项。

### 4.1 通用功能场景（产品主线）

以下场景不针对特定行业，用来驱动功能优先级和演示脚本。每个场景都能用“点界面”和“说一句话”两种方式完成。

| 编号 | 场景 | 用户要完成的事 | 用到的能力 | 现有能力覆盖 |
| --- | --- | --- | --- | --- |
| SC1 | 区域概况 | 选一个省 / 市 / 自定义范围，快速了解路网、水系、建筑、设施的总体情况 | 定位、图层统计、视野分析、报告 | 大部分已有，缺任意范围与报告 |
| SC2 | 找地方 | 按名称或类别查找地点，在地图上标出并列表查看 | 搜索、标记、属性查看 | 已有，需要全国地名库与分类搜索 |
| SC3 | 周边分析 | 某点或某条线周边一定距离内有哪些设施、多少道路、多大面积建筑 | 缓冲区、邻近查询、统计 | 缺缓冲区 |
| SC4 | 区域对比 | 两个或多个区域在同一指标上的差异（路网密度、设施数量、用地结构） | 行政区聚合、对比表、图表 | 缺聚合与对比 |
| SC5 | 专题制图 | 选图层、按类别配色、加标注，导出带图例和比例尺的地图图片 | 样式、出图 | 样式已有，缺出图 |
| SC6 | 我的数据上图 | 上传自己的点位 / 线路 / 范围数据，与开放数据叠加分析 | 数据上传、叠加分析 | 缺 |
| SC7 | 路线与可达范围 | 两点间最短路径；某地点出发一定距离 / 时间可到达的范围 | 路网分析 | 缺 |
| SC8 | 分析报告与分享 | 把一次分析的结论、表格、地图截图整理成报告，分享给他人查看或评论 | 报告、分享、评论 | 缺 |
| SC9 | 嵌入与集成 | 把地图或分析能力嵌到自己的系统 | API、嵌入 SDK、标准服务 | 缺 |

**场景模板**：把上面的场景沉淀成可复用模板（初始区域、图层组合、分析步骤、AI 提示词、报告格式）。平台先提供 6–8 个通用模板，后续行业模板（应急研判、选址评估、规划盘点、教学实验等）都以模板形式加入，不改平台代码。

## 5. 行业方向如何决定

目标客户暂不锁定，但要有机制在公测后做出选择：

1. **埋点（P6）**：记录每个场景、模板、工具、AI 指令的使用次数和完成率，以及用户注册时自愿填写的行业与用途。
2. **公测期访谈**：每月访谈 10 位活跃用户，记录他们在用哪个场景、缺什么。
3. **决策节点**：1.0 公测后 2 个月，按“使用量 × 付费意愿 × 合规难度”给候选行业打分，选 1–2 个行业做场景模板深化，进入阶段 3 的行业化工作。

候选方向（仅作参考，不在阶段 1–2 投入）：应急与公共安全、城市规划与基建、商业选址与零售、物流与交通、教育与培训、文旅。

## 7. 合规（SaaS 上线前必须确认）

是否对公众公开展示还不确定，但只要在公网提供地图服务，下面几项就绕不开。建议阶段 0 就请具备测绘资质的单位或律师做专项评估。

| 编号 | 事项 | 风险 | 默认做法（评估前） |
| --- | --- | --- | --- |
| C1 | 互联网地图服务资质 | 在互联网上提供地图服务，按规定可能需要“互联网地图服务”测绘资质 | 评估“注册登录后使用”能否不按公众服务认定；若不能，考虑与有资质的单位合作或申请资质 |
| C2 | 地图审图 | 公开展示的地图需要审图号；OSM 的国界、南海诸岛、台湾等表示不一定符合标准地图 | 底图和行政边界改用已审图的服务（如天地图）；OSM 数据只作为业务图层叠加 |
| C3 | 坐标系 | 公开地图对坐标系有要求 | 跟随合规底图的坐标系做转换，并在评估中确认业务图层的处理方式 |
| C4 | 敏感要素 | 军事、涉密设施等不得展示 | 入库时按标签黑名单剔除（D4） |
| C5 | ICP 备案 | 境内网站必须备案；在线收费还可能涉及经营性备案 | 域名与服务器确定后立即办理 |
| C6 | 等级保护 | 对外服务的信息系统通常要求等保二级及以上 | 按等保二级设计，正式商用前测评 |
| C7 | 个人信息保护 | 手机号、姓名、上传数据中的个人信息 | 隐私政策与用户协议；最小化采集；敏感字段加密；支持注销与数据导出 |
| C8 | 生成式 AI | 向公众提供生成式 AI 服务需要备案或登记 | 使用已完成备案的国内模型服务；输入输出做内容安全审核与留存 |
| C9 | 开源许可 | OSM 数据 ODbL 署名与衍生数据库共享义务；第三方依赖许可 | 页面、出图、报告保留署名；输出依赖许可清单 |

> 如果评估结论是公网门槛过高，备选路线是先做私有化版本，把 O8 / O9 提前；本计划的服务拆分和数据分层两条路线都能复用。
