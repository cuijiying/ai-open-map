## 一、作品名称

**智图灵 GeoMind Agent —— 全栈开源地图智能体**

命名释义：

- **智**：大模型与规则引擎驱动的智能决策；
- **图**：以开源地图（OSM）与矢量 WebGIS 为本体；
- **灵**：具备感知地图状态、规划步骤、调用工具、反思修正的 Agent「灵性」。

---

## 二、作品简介

智图灵是一套可私有化部署的**全栈开源地图智能体**。它面向中国省级 OpenStreetMap 数据，打通「下载 → 解析 → 入库 → 切片 → 对话操控 → 空间分析 → 报告生成」全链路，让用户用中文自然语言完成原本需要专业 GIS 软件与大量手工操作才能完成的工作。

系统采用 Spring Cloud 微服务架构（网关、入库、地图、对话），以 PostgreSQL + PostGIS 存储几何要素，以 MapLibre 渲染多省矢量切片；在此之上构建 **Orchestrator Agent（编排智能体）**，通过工具注册中心调度地图操控、空间分析、入库编排与报告叙事等子能力。规则引擎保障高频指令的确定性与低延迟，大模型负责开放表达与多步推理；本地 Ollama 与云端 OpenAI 兼容接口均可接入，数据与推理路径支持完全内网化。

**一句话价值**：把「会说话的开源地图」变成「会办事的地图 Agent」——可见、可控、可私有化、可开源复用。

## 三、应用场景

### 3.1 应急指挥快速研判

灾害发生后，指挥人员无需熟悉图层面板与空间 SQL，直接说：「定位到黄山，显示道路和水系，分析当前视野内道路里程，并标记医院。」Agent 自动完成定位、图层切换、PostGIS 相交分析与 POI 检索打点，分钟级形成初判材料。

### 3.2 城市规划与基建盘点

规划人员可请求：「对比安徽和浙江的道路分类数量，只显示高速公路，把道路改成红色。」系统跨省聚合统计、过滤路网子类并着色强调，辅助路网密度与结构对比。

### 3.3 高校 GIS / OSM 教学实验

教师一句话启动「下载安徽省 OSM 数据」；学生用对话完成显示图层、搜索大学、统计建筑等实验步骤。全程基于真实开源数据与可审计工具调用，适合课程实验与毕业设计底座。

### 3.4 政企私有化 WebGIS 底座

对数据不出域有要求的单位，可在内网部署整套服务，对接本地大模型。业务地图来自自建 PostGIS，不依赖商业地图 Token；Agent 降低业务人员使用门槛。

### 3.5 文旅区域导览与内容生产

文旅运营说：「去九华山，打开影像风格，查找附近景点。」Agent 切换底图主题、检索兴趣点并生成简短导览摘要，服务内容生产与数字化导览。

## 四、要解决的问题与创新点

### 4.1 痛点

1. **传统 WebGIS 交互重**：图层、筛选、缓冲、统计分散在多个面板，非专业用户学习成本高。
2. **商业地图难私有化**：Token、配额与合规限制阻碍内网与开源交付。
3. **开源 OSM 上手难**：PBF 下载、解析、投影、切片、发布链路长，缺少「对话式」封装。
4. **普通 ChatBot 不懂地图**：只会聊天，不能真正改地图状态、算空间指标、跑数据任务。

### 4.2 创新点

| 创新点 | 说明 |
| --- | --- |
| 全栈地图 Agent | 不是外挂聊天框，而是覆盖数据生产到地图消费的闭环智能体 |
| 规则 + LLM + 工具调用 | 高频指令走规则（可测、低延迟），复杂意图走多步 ReAct |
| 开源可私有化 | OSM + 自建切片 + 本地模型，满足内网与开源社区双重场景 |
| 多省同图与异步入库 | 入库期间已发布省份仍可浏览；Agent 可编排跨省任务 |
| 场景化 Skills | 应急/规划/教学等技能包可插拔，同一底座多业务复用 |
| 结果可审计 | 每次工具调用可追踪，分析结果带来源表与指标说明 |

## 五、系统架构

### 5.1 总体架构

```text
浏览器（React + MapLibre）
        │  /api
        ▼
   map-gateway（Spring Cloud Gateway）
        ├── map-ingest   下载 / 解析 / 发布 OSM
        ├── map-geo      矢量切片 / 搜索 / 统计 / 分析
        └── map-ai       Agent 编排 / 规则 / LLM / 工具
                │
                ▼
        PostgreSQL 16 + PostGIS（ai_open_map）
```

### 5.2 Agent 逻辑架构

用户自然语言进入 **Orchestrator Agent**：

1. **感知**：读取地图上下文（中心、缩放、bbox、可见图层、已选省份、风格）。
2. **规划**：分解为有序工具调用计划（可多步）。
3. **执行**：经 Tool Registry 调用 MapOps / GeoAnalyst / IngestOps / ReportOps。
4. **反思**：工具失败或结果为空时调整计划重试；成功则汇总回复与地图动作。
5. **记忆**：将会话、中间结论与地图状态写入会话存储，支持指代（「再分析一下」「换浙江」）。

### 5.3 技术栈

| 层级 | 技术 |
| --- | --- |
| 前端 | React 18、TypeScript、Vite、Ant Design、MapLibre GL |
| 网关 | Spring Cloud Gateway、可选 Nacos |
| 业务服务 | Spring Boot 3.2、MyBatis、Druid |
| 空间库 | PostgreSQL 16、PostGIS 3.4、pg_trgm |
| OSM | Osmosis Reader、Geofabrik 省级 PBF |
| 智能 | 规则对话引擎、OpenAI 兼容 LLM、Agent 工具编排 |
| 运行 | JDK 17、Node.js 22、本地一键脚本 |

## 六、核心能力详解

### 6.1 开源地图数据管道

- 支持中国多省区域从 Geofabrik 下载 PBF；
- 解析 node/way/relation（面关系），分类写入九大图层；
- 分区发布：单省发布不阻塞其他省切片；
- 可选全国低缩放瓦片预生成，提升首屏与宏观浏览体验。

### 6.2 矢量地图与多省同图

- 九图层：道路、铁路、水系线、水体、建筑、土地利用、行政区划、兴趣点、地名；
- 前端可勾选多省，同一 MVT 瓦片聚合渲染；
- 支持浅色 / 深色 / 彩色 / 纸图 / 影像 / 素底等风格，以及图层着色。

### 6.3 地图操控工具（MapOps）

| 工具 | 能力 |
| --- | --- |
| show / hide / only_layers | 显示、隐藏、独显图层，支持高速等子类过滤 |
| fly_to | 定位到省、市、景点等 |
| markers / clear_markers | 搜索结果打点与清除 |
| set_style / paint_layer | 底图主题与图层颜色 |

### 6.4 空间分析工具（GeoAnalyst）

| 工具 | 能力 |
| --- | --- |
| layers | 各图层要素总量 |
| stats | 图层子类 TopN 统计 |
| search | 名称/类型模糊检索并定位 |
| analyze | 当前视野内数量、长度、面积（PostGIS） |
| compare_regions | 多省指标对比表 |

### 6.5 入库编排工具（IngestOps）

- `start_ingest`：按省份创建下载解析任务；
- `watch_job`：轮询进度与日志，完成后自动续执行后续地图指令；
- 支持「下载完成后再显示道路」这类跨时长计划。

### 6.6 报告叙事工具（ReportOps）

将分析表、关键结论与建议下一步动作汇总为结构化简报（对话内表格 + Markdown 摘要），便于汇报与存档。

### 6.7 规则优先与模型兜底

- **规则引擎**：覆盖显示/隐藏/定位/统计/查找/分析/风格/着色等高频中文指令，离线可用、结果可单测；
- **大模型**：规则未命中时，按系统提示输出受约束的工具调用计划；
- **安全边界**：模型不能直接拼 SQL，只能触发白名单工具。

## 七、典型演示流程（路演建议）

### 演示 A：一句话看懂路网

1. 「定位到合肥，只显示高速公路」
2. 「分析当前视野内的道路里程」
3. 地图飞入、图层过滤、表格输出里程——展示 Agent 感知视野并调用 PostGIS。

### 演示 B：跨省对比

1. 勾选安徽、浙江（或口述切换）
2. 「对比两省道路分类数量」
3. 输出对比表，并可「把道路改成红色」强化可视化。

### 演示 C：数据生产闭环

1. 「下载浙江省数据，完成后显示水系和道路」
2. Agent 创建入库任务、播报进度，成功后自动执行图层动作。

### 演示 D：应急简报

1. 「定位黄山，显示道路和建筑，查找医院，生成简报」
2. 展示多工具串联与 ReportOps 输出。

## 八、开源与合规

- 地图数据来自 OpenStreetMap，使用时保留署名，遵循 ODbL；
- 工程以可运行的全栈仓库形态组织，文档覆盖架构、库表、接口与运行方式；
- 模型密钥在接口层打码；支持无密钥本地模型，降低试用门槛；
- 鼓励在保留 OSM 署名与开源协议要求的前提下二次开发 Skills 与行业插件。
